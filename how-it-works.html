01 / How it works

From pull request to security answer.

A small Terraform change can open a service to the internet or widen a role's permissions, and this is easy to miss in a normal code review.

Step 1

A developer changes infrastructure code and opens a pull request.

Step 2

WCI receives the change and compares the before and after security state.

Step 3

WCI identifies security-relevant changes and evaluates their risk.

Step 4

WCI posts the result as a comment on the pull request.

Change-awareOne change, one answer.
Terraform change→ WCI→ PR comment

Every result states

  • What changed
  • The security impact
  • The risk level
  • Before and after values
  • Why it matters
  • The resource or identity involved

Scanners find misconfigurations. WCI focuses on what one specific change does to security — it does not compete on rule count.
