06 / Analysis model

Evidence first. Claims second.

Each layer keeps the facts, assumptions and confidence of the layer before it.

LayerQuestionV1
Configuration factsWhat exists and how is it configured?In scope
Finding engineWhich rule predicates are satisfied?In scope
Relationship graphWhat is connected to what?Future
Permission analysisWhat can an identity actually do?Future
Exposure analysisIs there a supported path to the resource?Future
Attack-path analysisWhat path crosses controls?Future
Risk engineHow does context change priority?Future

Levels of a claim

LevelExampleRule
ObservedThe parsed rule allows TCP/22 from 0.0.0.0/0State it
DerivedAny IPv4 source is permitted by that ruleState it, naming the source
Context-dependentA resource using the group may be internet-reachableConditional only
Potential impactExposure can increase attack surfaceConditional only

Precise, not alarming

A security group proves the group is permissive. It does not prove an attached workload, a public address, a route, a listening service, or exploitability.

  • Say: “This rule permits any IPv4 source to attempt TCP/22.”
  • Do not say: “This instance is definitely exposed.”

First rule: public SSH

One finding per matching ingress rule on an aws_security_group that allows 0.0.0.0/0 on TCP/22 — or on all protocols. Baseline severity High: a policy classification, not proven reachability.
